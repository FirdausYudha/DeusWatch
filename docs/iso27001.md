# ISO 27001 control evidence

DeusWatch can produce evidence that security controls were **operating** during a period, mapped to
the ISO/IEC 27001:2022 Annex A references an auditor works from.

```
GET /api/compliance/iso27001?days=90
GET /api/compliance/iso27001?days=90&format=csv
```

Needs `manage_settings`: every part of this is readable elsewhere by someone with the right
permission, but one document combining the account roster, the audit log and the response history
is a summary of the deployment that deserves the higher bar.

## Read this before you send it to anyone

**This is evidence, not a compliance determination.** DeusWatch cannot know whether an organisation
meets the standard, and nothing it produces should be presented as saying so.

Certification covers policy, governance, risk assessment, training, physical security and supplier
management. DeusWatch sees none of those. It sees the estate, and it can show what happened on it.
That is one input an auditor weighs among many.

**The control mapping is a starting point.** Which Annex A control a piece of evidence supports is
a judgement your auditor makes, not a question this tool settles. Sixteen controls are mapped here
because they are the ones a monitoring product plausibly speaks to; the mapping is written to be
argued with.

## What is in the report

| Control | What DeusWatch contributes |
|---|---|
| A.5.7 Threat intelligence | Indicator lookups performed, with source and date |
| A.5.15 Access control | Failed and successful sign-ins across the estate |
| A.5.16 Identity management | Accounts that exist today, their roles, which are disabled |
| A.5.18 Access rights | Every account and permission change, with who made it |
| A.5.24 Incident management planning | Response playbooks defined and whether enabled |
| A.5.25 Assessment and decision on events | Alerts raised and how many became tickets |
| A.5.26 Response to incidents | Blocks and containment carried out, with who approved |
| A.5.28 Collection of evidence | How far back the event record reaches; retained file versions |
| A.6.8 Event reporting | Tickets raised, by whom, how many automatically |
| A.8.7 Protection against malware | Process classifications and file-hash verdicts |
| A.8.8 Technical vulnerabilities | Findings by severity and when each endpoint was last scanned |
| A.8.9 Configuration management | Monitored paths and changes detected |
| A.8.15 Logging | Event volume and how many endpoints actually reported |
| A.8.16 Monitoring activities | Rules enabled and the alerts they produced |
| A.8.20 Networks security | Addresses blocked and the backend that carried each block |
| A.8.32 Change management | File integrity changes, with the responsible account where who-data is on |

## A control with no evidence is a GAP, not a blank

This is the part that makes the report worth carrying into an audit.

A control with nothing to show is reported as a gap, with a line saying what to check. It is never
quietly omitted, because in a document like this **a missing row reads as "not asked" rather than
"the answer was empty"**, and that is the one impression an evidence report must not leave.

The gap text also names the ambiguity where one exists. "No alerts were raised" has two readings:

> Either the estate was quiet or detection is not reaching it. The two look identical here, so
> check that rules are enabled and agents are reporting before recording this as calm.

That matters more than the count beside it. A quiet period and a broken sensor produce the same
zero, and only one of them is good news.

## Its own boundary is in the report

The export ends with what it does **not** cover: policy and governance, risk assessment, people
controls, physical controls, supplier management, business continuity, backup. An auditor reading
sixteen controls needs to know the other seventy-seven were excluded on purpose.

The disclaimer is written into the CSV itself, not only onto the screen that produced it. A file
reaches people detached from wherever it was downloaded, and a row of counts with no caveat
attached is exactly how an evidence report gets read as a claim.

## Where this is genuinely useful

An organisation that has not started certification, which is where the field discussion found this
hospital, usually discovers that the hardest part is not having controls but **proving they ran**.
A tool already watching the estate holds most of that proof. This turns it into a document rather
than a database someone has to query under time pressure.

Run it for the period your audit covers, read the gaps first, and fix those before the auditor
reads them for you.
